## Архитектура (main)
- Node.js 20 (CommonJS), Express 5, better-sqlite3. Один процесс `server.js` (255 строк) + `meta.js` (Meta Graph API). Фронт: SPA vanilla JS в `public/` (дашборд, RU/EN/UK, мобильная вёрстка).
- Порт 8787, HOST по умолчанию 127.0.0.1 (в Dockerfile 0.0.0.0, но compose публикует только 127.0.0.1:8787; внешний доступ — Tailscale). launchd plist в `deploy/`.
- БД: SQLite `data/studio.db` (WAL), универсальная таблица `items(col,id,data JSON)` + `meta(k,v)`. Generic CRUD `/api/:col[/:id]`.
- Очередь задач: коллекция `tasks` (status queued/…); планировщик `setInterval(tick, 30s)` — `core.schedulerTick`, автоотчёт раз в 3 дня, публикация Meta (`meta.tick`), ежедневный бэкап JSON (хранится 14).
- Director chat: `/api/director/chat` → Ollama `/api/chat` (qwen3:8b, format json) → задачи агентам; fallback rule-based.
- Интеграции (seed): Ollama :11434, OpenCode :4096, Docker Engine TCP :2375, Open WebUI :3000; `/api/integrations/:id/test` делает HTTP-запрос с сервера на URL из БД.
- В main **нет** реального исполнения агентов/shell (child_process не используется), нет Blender/Video Factory кода — только данные/UI. News Engine — шаблоны задач (search/factcheck/script).
- Auth: scrypt-пароль в `meta.users`, случайные сессии (cookie `mk_session` или Bearer), сессии хранятся в БД открытым токеном; rate-limit логина по IP. `/api/health`, `/api/auth/*`, `/api/meta/oauth/callback` — без auth.
- Секреты: токены Meta AES-256-GCM в `meta`, ключ из `STUDIO_SECRET_KEY` или `data/secret.key` (0600, рядом с БД). Meta App ID/secret — env или Settings.
- Логи: коллекция `logs` в SQLite (последние 2000) + stdout/err в `data/studio*.log`.
- Тесты: только `scripts/smoke.mjs` (playwright-core).
- Мониторинг: `/api/system` (CPU, RAM, диск, loadavg, uptime, lastSchedulerTick, lastBackup).

## Риски безопасности
1. **SSRF**: `/api/integrations/:id/test` и Director fetch идут на URL, задаваемый через generic CRUD (`PUT /api/integrations/...`) — любой залогиненный клиент/XSS может дергать внутренние сервисы (в т.ч. Docker :2375).
2. **Docker Engine TCP :2375** в seed — без TLS это root-эквивалент; не включать.
3. Generic CRUD без валидации схемы: можно перезаписать `agents`, `integrations`, `tasks` (status/approval флаги) — обход approval, если runner доверяет полям.
4. В main нет Host-check/CSRF/CSP (исправлено только в feat/macos-app) — DNS-rebinding на 127.0.0.1:8787.
5. Сессии хранятся в БД нехешированными (в ветке — hashed); `secret.key` лежит рядом с БД и попадает в тот же каталог бэкапов → компрометация `data/` = все токены.
6. `/api/restore` и `/api/reset` разрушительны для любого аутентифицированного запроса; бэкапы JSON без шифрования (содержат логи/данные, не секреты из meta).
7. **Prompt injection**: текст пользователя/новостей/комментариев (comments sync из FB/IG) попадает в промпты Ollama и в OpenCode (`task.title+description` → `opencode run`). Задачи из LLM-плана создаются автоматически; комментарии соцсетей — внешний недоверенный ввод. Sandbox ограничивает запись, но не сеть/чтение (проверить профиль).
8. Upload до 500 МБ, `express.json` 50 МБ — DoS по RAM/диску; `/files` отдаётся статикой (content-type по расширению → stored XSS при html/svg).
9. Ошибки 500 возвращают `err.message` клиенту.
10. Dockerfile HOST=0.0.0.0 — безопасно только с compose-биндингом 127.0.0.1.

## Предлагаемые точки интеграции
- **Watchdog**: `/api/health` + `/api/system.lastSchedulerTick` (tick 30s → алерт при >90s), `runner.busy`/`/api/runtime`, Ollama `/api/tags`; launchd KeepAlive уже есть. Отдельный процесс/launchd-job, пишет в `logs` через API или в свою коллекцию `watchdog`; kill/restart зависших задач runner через AbortController (runner.stop).
- **Resource Manager**: обернуть `runner.tick` семафором по RAM (24 ГБ: Ollama-модель + Blender/ffmpeg несовместимы одновременно), использовать `os.freemem`, `loadavg`, Ollama `/api/ps` (выгрузка моделей `keep_alive:0`); поле `resources` в задаче (gpu/ram class) + приоритет из `tasks.priority`.
- **Mobile Control Center**: существующий адаптивный SPA + Tailscale; добавить ограниченный набор эндпоинтов (`/api/mobile/summary`, approve/reject задач и очереди публикаций, pause runner), отдельный scoped-токен (по аналогии с `x-studio-app-token`), без доступа к generic CRUD/restore/reset; push через ntfy/Telegram.
