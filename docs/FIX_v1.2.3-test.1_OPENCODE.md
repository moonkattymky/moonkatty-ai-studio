# v1.2.3-test.1 — «Агент OpenCode не записал scene_params.json»

Только TEST-сборка (flavor test вшит, публикация выключена, автозапуск/обновления выключены, пароль только в Keychain
«MOONKATTY AI STUDIO.test», 127.0.0.1:4097, Basic Auth OpenCode НЕ отключается). Релиз не публикуется. v1.1.2 не меняется.

## Диагноз (код a2a35c8)
1. **Неотвеченный запрос разрешения (edit=ask)** — НЕ причина. Студия опрашивает `GET /permission` и отвечает
   `once/reject` (lib/executors/design3d.js:84–91). При запросе в журнале была бы строка «Разрешение OpenCode …» — её нет.
2. **Папка проекта вне worktree → external_directory=deny** — НЕ причина. Сессия создаётся с `?directory=<vdir>`
   (lib/opencode-client.js:27,35; design3d.js:68), т. е. корень инстанса OpenCode = projects3d/<проект>/v001, а
   scene_params.json лежит внутри. К тому же инструменты вообще не вызывались.
3. **Модель не вызывает инструменты** — ПОДТВЕРЖДЕНО («Инструменты: нет»). qwen2.5-coder:7b через Ollama
   (opencode/opencode-studio.json:10,12, OpenAI-совместимый `/v1`): Ollama на машинах < 24 GiB VRAM даёт контекст 4096;
   системный промпт OpenCode + схемы инструментов в него не помещаются и обрезаются, а qwen2.5-coder часто печатает
   вызов инструмента текстом вместо tool_call (sst/opencode#2728). `num_ctx` в opencode.json через `/v1` не передаётся.
   Наш код при нуле вызовов просто падал (design3d.js:99–110) без запасного пути.

## Исправление
- На шаге «Агент OpenCode» агенту не выдаётся ни одного инструмента: в `prompt_async` передаётся `tools` с
  write/edit/patch/bash/webfetch… = false, конфиг сервера `edit/write/patch = deny` (допускается и старый `ask`),
  bash/webfetch/external_directory = deny. Любой запрос разрешения отклоняется (никогда не одобряется автоматически).
- Агент возвращает параметры ТЕКСТОМ JSON. Студия извлекает один JSON-объект (```json или первый `{…}`, ≤ 20000 симв.),
  проверяет строгой схемой (типы, перечисления, диапазоны, длины, без лишних ключей, title без `/` → без путей) и сама
  пишет scene_params.json только в папку версии: realpath внутри папки, папка и файл не символические ссылки,
  временный файл O_EXCL|O_NOFOLLOW (0600) + rename.
- Если агент создал любой файл в папке или выполнил запрещённый инструмент — задание останавливается.
- Неверный/пустой JSON → один повторный запрос с перечнем ошибок; затем понятная ошибка на русском с подсказкой про
  OLLAMA_CONTEXT_LENGTH. Ошибка модели и таймаут — тоже понятные сообщения.

## Что можно попробовать прямо сейчас на установленной v1.2.3-test (без пересборки)
**Это не меняет и не касается v1.1.2.** Ничего не устанавливается.

1. Увеличить контекст Ollama (главная причина «Инструменты: нет»):
   ```
   launchctl setenv OLLAMA_CONTEXT_LENGTH 32768
   ```
   затем полностью закрыть Ollama (иконка в строке меню → Quit) и запустить снова. Либо в приложении Ollama:
   Settings → Context length → 32k. Проверка: `ollama run qwen2.5-coder:7b "hi"`, затем `ollama ps` — в колонке
   CONTEXT должно быть 32768. После этого перезапустить OpenCode (serve.sh) и повторить задание в студии.
   Если памяти не хватает (Mac mini 24 ГБ), поставьте 16384.
2. Если и после этого «Инструменты: нет» — сменить модель в студии (Настройки → 3D Studio → модель OpenCode) на
   `ollama/qwen3:8b` (она уже есть в конфиге и надёжнее вызывает инструменты; сначала `ollama pull qwen3:8b`).
   `qwen2.5-coder:14b` (~9 ГБ) тоже помещается в 24 ГБ при контексте 16–32k, но в конфиг v1.2.3-test она не внесена.
3. Не нужно и НЕЛЬЗЯ ставить `edit: allow`, `external_directory: allow` или отключать пароль OpenCode — это не поможет
   (инструменты не вызывались вовсе) и ослабит защиту.

Без пересборки гарантии нет: v1.2.3-test всё ещё требует, чтобы маленькая модель сама вызвала инструмент записи.
Исправление v1.2.3-test.1 убирает эту зависимость.
