## r3 — QA-NODE-001, остаток (повтор после быстрого перезапуска)
- Было: кэш nonce только в памяти + нижняя граница = время старта. Запрос с меткой «в будущем» (до +30 с), принятый до перезапуска, мог пройти повторно, если координатор перезапустился раньше этой метки.
- Стало: `replay-floor.json` в каталоге узлов (0600, запись → fsync → rename → fsync каталога) ДО того, как запрос принят:
  - `nowHwm` — верхняя отметка часов координатора, поднимается шагами по 3 с (не больше одного fsync на 3 с при обычной нагрузке);
  - `scopes` — по каждому узлу/заявке: наибольшая принятая метка, лежащая выше `nowHwm` (допустимый сдвиг вперёд).
  - После перезапуска принимается только `ts > nowHwm` и `ts > scopes[узел]`. Любой ранее принятый запрос ниже одной из границ → `E_REPLAY`.
- Почему так, а не хранить все nonce: файл маленький, без nonce/подписей/токенов; fsync редкий; доказуемо покрывает каждый принятый запрос.
- Часы координатора ушли назад: всё отклоняется, пока часы не догонят `nowHwm` (отказ безопасный, событие `clock_back` в аудите при > 60 с).
- Файла нет или он испорчен: граница = время старта процесса (прежнее правило).
- Не удалось записать границу: запрос отклоняется (429, повторяемо), принятия без записи нет.
- Цена: после перезапуска в пределах 3 с свежие запросы отклоняются до 3 с; узел, который последним прислал метку +N с, после перезапуска должен прислать метку выше неё (до 30 с при исправленных назад часах узла). Агент 0.2.2 (r3) на `E_REPLAY` повторяет запрос с новой подписью через 3 с (раньше любой 401 = пауза 60 с); проверено настоящим агентом при перезапуске координатора.
- Подписи, окно ±30 с, nonce, токены — не ослаблены.
- Тесты: `test/ops/replay-restart.test.js` (быстрый перезапуск 1 мс/0,5 с/2 с, метки now и +29 с, законный сдвиг ±29 с, ±31 с отклоняются, другой узел не блокируется, часы назад, файл потерян/испорчен, файл не записывается), `test:ops:studio` — настоящий перезапуск процесса server.js (SIGKILL) с повтором по TLS.

## Исходный zip и версия git
`git archive` в разных версиях git пишет zip по-разному (замечание Studio 4 r2). Рядом с хэшем записывается `git --version` (`.gitversion`); хэши сравнивать только при одной версии git. Проверка содержимого без зависимости от версии: `bash scripts/node/verify-source-zip.sh <zip> <commit>` (сверка git blob-хэшей всех файлов).
