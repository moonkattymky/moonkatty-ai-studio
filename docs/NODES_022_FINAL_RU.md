## r3 — QA-NODE-001, остаток (повтор после быстрого перезапуска)
- Было: кэш nonce только в памяти + нижняя граница = время старта. Запрос с меткой «в будущем» (до +30 с), принятый до перезапуска, мог пройти повторно, если координатор перезапустился раньше этой метки.
- Стало: `replay-floor.json` в каталоге узлов (0600, запись → fsync → rename → fsync каталога) ДО того, как запрос принят:
  - `nowHwm` — верхняя отметка часов координатора, поднимается шагами по 3 с (не больше одного fsync на 3 с при обычной нагрузке);
  - `scopes` — по каждому узлу/заявке: наибольшая принятая метка, лежащая выше `nowHwm` (допустимый сдвиг вперёд).
  - После перезапуска принимается только `ts > nowHwm` и `ts > scopes[узел]`. Любой ранее принятый запрос ниже одной из границ → `E_REPLAY`.
- Почему так, а не хранить все nonce: файл маленький, без nonce/подписей/токенов; fsync редкий; доказуемо покрывает каждый принятый запрос.
- Часы координатора ушли назад: всё отклоняется, пока часы не догонят `nowHwm` (отказ безопасный, событие `clock_back` в аудите при > 60 с).
- Файла нет или он испорчен: граница = время старта процесса (прежнее правило).
- Не удалось записать границу: запрос отклоняется (429, повторяемо), принятия без записи нет.
- Цена: после перезапуска в пределах 3 с свежие запросы отклоняются до 3 с; узел, который последним прислал метку +N с, после перезапуска должен прислать метку выше неё (до 30 с при исправленных назад часах узла). Агент 0.2.2 (r3) на `E_REPLAY` повторяет запрос с новой подписью через 3 с (раньше любой 401 = пауза 60 с); проверено настоящим агентом при перезапуске координатора.
- Подписи, окно ±30 с, nonce, токены — не ослаблены.
- Тесты: `test/ops/replay-restart.test.js` (быстрый перезапуск 1 мс/0,5 с/2 с, метки now и +29 с, законный сдвиг ±29 с, ±31 с отклоняются, другой узел не блокируется, часы назад, файл потерян/испорчен, файл не записывается), `test:ops:studio` — настоящий перезапуск процесса server.js (SIGKILL) с повтором по TLS.

## r4 — запись границы повтора: отказ при любой неподтверждённой записи
- Ошибка fsync каталога больше не игнорируется: запрос отклоняется (429, повторяемо). Платформы: ext4/xfs/btrfs/tmpfs (Linux) и APFS/HFS+ (macOS) поддерживают fsync каталога; на ФС, которая его не поддерживает (некоторые сетевые/FUSE-тома), подписанные запросы узлов будут отклоняться — каталог данных студии держать на локальном диске. Принять запрос без подтверждённой записи нельзя: иначе после сбоя питания повтор снова возможен.
- Ошибка open/write/fsync/rename: `.tmp` удаляется, прежний `replay-floor.json` не трогается (замена только атомарным rename).
- Найдено при этом: после неудачной записи следующий запрос мог быть принят без записи (граница в памяти уже поднята). Исправлено: граница остаётся «грязной», пока запись не подтверждена.
- Тест: `test/ops/replay-restart.test.js` (r4) — внедрённые сбои open .tmp / write (частичная запись) / fsync файла / rename / fsync каталога.

## r5 — QA-R4-001: Tailscale Serve для узлов НЕ используется (рекомендации убраны)
**Решение и основания.** Node API координатора v1.3.0-test Serve не требует:
- `lib/ops/nodes-server.js` (шапка): Node API — отдельный HTTPS-слушатель с самоподписанным сертификатом, узлы закрепляют его SHA-256; слушает 127.0.0.1 и один адрес Tailscale 100.x; «Tailscale Serve/Funnel are NOT used or enabled».
- `lib/ops/nodes.js`: заголовки Serve по умолчанию не доверяются (`trustServeHeaders=false`, QA-NODE-002).
- `docs/SECURITY_RECHECK_v1.2.4-test.md`: «Tailscale Serve и Funnel не используются»; `docs/MAC_TEST_NODES_v1.2.4.md`: `NODE_TLS_MODE=tailscale` и `*.ts.net` из примера убрать.
- Serve в студии используется только для веб-панели/iPhone PWA (`tailscale serve --bg 8787`, `docs/CONNECT_MAC.md`, `docs/INSTALL_MAC.md`) — это координатор, не узлы; не менялось.
- Схема `*.ts.net:8443` + `NODE_TLS_MODE=tailscale` — из старого трека 0.2.0 (`docs/ops/NEWS_NODE_IMAC.md`, `MONITOR_NODE_MACBOOK.md`), она требует новой настройки Serve на Mac mini (запрещено) и доверяет публичному CA вместо закреплённого сертификата.

**Что сделано.**
- Агент и подключение: `NODE_TLS_MODE=tailscale` больше не поддерживается — `config()`, `client()` и `enroll()` отклоняют его с понятным сообщением (`E_TLS_MODE`); подключение всегда `pinned`, отпечаток обязателен (в т.ч. для имени `*.ts.net`). Обоснование отказа вместо «не рекомендуется»: режим ослабляет проверку TLS (публичный CA вместо пина) и требует менять Tailscale на Mac mini.
- `node-agent.env.example`: по умолчанию `NODE_TLS_MODE=pinned`, `https://100.x.y.z:8690`, сертификат и отпечаток; убрана подсказка ручной записи токена.
- `enroll.html`: адрес `https://100.x.y.z:8690`, отпечаток обязателен. plist, комментарии agent.js, `studio-connection-test.mjs` — без Serve.
- `fetch-ffprobe.sh`: убрано `xattr -d com.apple.quarantine` (curl не ставит карантин; снимать его не нужно и не разрешено политикой).
- `NODES_INSTALL_RU.md`: формулировки про Serve уточнены (Serve веб-панели не трогать, для узлов не настраивать).
- Старые инструкции 0.2.0 (`docs/ops/NEWS_NODE_IMAC.md`, `MONITOR_NODE_MACBOOK.md`, `NODES_IMAC.md`, `NODES_MACBOOK.md`) помечены «УСТАРЕЛО» со ссылкой на `NODES_INSTALL_RU.md`.
- Тест `test/ops/node-advice-scan.test.js`: сканирует все текстовые файлы собранного пакета и актуальные документы (Serve/Funnel, `ts.net:8443`, `NODE_TLS_MODE=tailscale`, 0.0.0.0, `spctl --master-disable`, снятие карантина, sudo, токен открытым текстом, секрет/код в argv; строки с явным запретом допускаются), проверяет безопасные значения env.example и баннеры устаревших документов; тот же сканер на содержимом r4 (`e562345`) находит нарушения.
