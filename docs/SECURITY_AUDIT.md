## Модель безопасности (кратко)

- **Сеть**: сервер слушает только 127.0.0.1. Удалённый доступ — только через `tailscale serve`, имя `*.ts.net` нужно явно добавить в `allowedHosts` в `desktop.json`.
- **Аутентификация**: пароль (scrypt) → cookie сессии HttpOnly, SameSite=Strict; вход ограничен 5 неудачными попытками в минуту. Окно приложения входит по локальному токену (`app-token`, файл 0600): он передаётся только в заголовке из main-процесса Electron к 127.0.0.1, недоступен JS страницы; принимается только с loopback и без чужого Origin.
- **Остаточный риск, локальные процессы**: любая программа, запущенная от вашего пользователя macOS, может прочитать `app-token`, базу и ключ (как и любые данные пользователя). Keychain тоже не защищает от процессов того же пользователя, которым вы разрешили доступ. Защита от вредоносного ПО на вашем Mac этим приложением не обеспечивается.
- **Агенты**: только argv-вызовы (`spawn` без shell), фиксированные пути (`/usr/bin/security`, `/bin/launchctl`, `/usr/bin/sandbox-exec`); ответы LLM только сохраняются как черновики на утверждение и никогда не исполняются. Агенты не меняют системные настройки и не читают секреты. Публикация и ответы — только после утверждения человеком.
- **Prompt injection**: текст новостей/комментариев может повлиять на черновик LLM, но не на действия: план Director создаёт только обычные задачи (не задачи кода), а задачи кода требуют отдельного одобрения и выключены по умолчанию.
- **Обновления**: только HTTPS-запрос к GitHub API закреплённого репозитория; предложение показывается, только если в релизе есть zip и `.sha256`, и они совпадают с digest, который вычисляет сам GitHub. Ничего не скачивается и не устанавливается автоматически: архив скачивается в браузере (получает карантин Gatekeeper). Это защищает от повреждения, но **не** от компрометации самого репозитория/аккаунта GitHub — для этого нужна подпись Developer ID.

## 1.1.2 — пароль OpenCode server (HTTP Basic Auth)

Ветка `feat/opencode-auth`. Код: `lib/opencode-auth.js`, маршруты `/api/opencode/auth` (GET/PUT), `/api/opencode/test` (POST) в `server.js`, карточка в «Настройках». Тесты: `scripts/opencode-auth-test.mjs` (51 проверка; локальные mock-серверы OpenCode, **требующие** Basic Auth, фиктивный пароль `test-fake-pw-123`).

| Требование | Реализация | Как проверено |
|---|---|---|
| Пароль только в macOS Keychain | generic password, служба «MOONKATTY AI STUDIO», учётная запись `opencode-server-password`, через `/usr/bin/security` | Linux: тестовая заглушка `security` (только `NODE_ENV=test` и не в Electron). **На Mac не проверено** |
| Пароль не в argv | `security -i`, команда в stdin, пароль hex (`-X`); argv = `["-i"]`; окружение дочернего процесса урезано | тест: журнал argv заглушки не содержит ни пароля, ни hex |
| Нет запасного хранилища | без Keychain (Linux, Docker, браузер) — «Не подключено», PUT пароля → 409 | тест на втором сервере без Keychain: файлы данных без пароля |
| API не отдаёт пароль | только `hasPassword: boolean`; generic CRUD вырезает `password/authorization/lastTest` у integrations | тест: ни один ответ API не содержит пароль/base64 |
| Логи, аудит, ошибки | явная замена пароля в тексте результата + `redact()` (новые правила: `Basic …`, `authorization: …`, `OPENCODE_SERVER_PASSWORD=…`); ошибки разбора JSON больше не логируют/не возвращают `err.message` (Node цитирует тело запроса) | тесты: журнал, stdout/stderr сервера, mock-сервер 403, возвращающий заголовок Authorization в теле |
| SQLite, WAL, бэкапы | пароль туда не пишется никогда | тест: бэкап создаётся, затем поиск пароля/base64/hex во **всех** файлах каталога данных |
| localStorage | поле пароля очищается после отправки; в браузерном режиме не сохраняется | тест Playwright: localStorage/sessionStorage/DOM |
| Только loopback | `127.0.0.1`, `localhost`, `::1`; запрет userinfo в URL, query/hash, не-http(s); `redirect: manual` (пароль не уходит на другой адрес). Удалённый адрес — только `STUDIO_OPENCODE_ALLOW_REMOTE=1` в окружении сервера | тесты: LAN, внешний хост, `127.0.0.1.nip.io`, file:, javascript:, generic CRUD |
| CSRF/токен | новые маршруты под общей проверкой сессии/app-token и `X-Studio-Request` + Origin/Sec-Fetch-Site | тесты 401/403 |
| Валидация | логин `[A-Za-z0-9._@-]{1,64}`, пароль 1–256 печатных ASCII (нет перевода строки — безопасность протокола stdin), только разрешённые поля | тесты |

Найдено и исправлено попутно: (1) обработчик ошибок Express писал в журнал и возвращал `err.message` от body-parser, который может содержать фрагмент тела запроса (например, пароль) — исправлено; (2) через generic `PUT /api/integrations/opencode` можно было задать любой URL — теперь та же проверка loopback.

Ограничения 1.1.2: пароль с не-ASCII символами не поддерживается (ограничение вывода `security -w`); разбор кавычек в `security -i` на реальном Mac не проверен; ACL записи Keychain принадлежит `/usr/bin/security` (любой процесс пользователя, вызывающий `security`, может прочитать запись без запроса — так же, как ключ шифрования 1.1.1); исполнитель задач (`runner.js`) по-прежнему запускает OpenCode CLI, а не ходит в `opencode serve` — пароль используется только для проверки подключения.

## Оставшиеся риски (прямо)

1. Сборка **не подписана Developer ID и не нотаризована**; ad-hoc подпись ничего не говорит о происхождении. Проверка подлинности — только сверка SHA-256 и (лучше) сборка из исходников самостоятельно.
2. **Ничего не проверено на macOS**: Gatekeeper, launchd, Keychain, sandbox-exec, fuses в работе, шифрование cookies. См. `docs/MAC_TEST_CHECKLIST.md`.
3. Код сервера лежит в `app.asar.unpacked` — проверка целостности ASAR его **не покрывает**; ad-hoc подпись покрывает (`codesign --verify`), но только если её проверяют.
4. `sandbox-exec` объявлен Apple устаревшим; профиль OpenCode не тестировался; сеть для OpenCode открыта (возможна утечка содержимого папки задачи).
5. `/api/health` без аутентификации раскрывает pid/версию/источник ключа (только для 127.0.0.1 и разрешённых хостов).
6. Сторонний JS панели не используется, но страницы Graph API отдают изображения по https — CSP разрешает `img-src https:`.
7. XSS в панели проверен выборочно (поиск неэкранированных вставок), не формально.

## 1.2.0 — агент 3D DESIGN (OpenCode server API + Blender)
**Новая поверхность:** HTTP-клиент OpenCode server, запуск Blender, папки проектов, API заданий.
- **Пароль OpenCode** читается из Keychain при каждом задании, хранится только в памяти и уходит только в заголовок Authorization к loopback-адресу. Перенаправления не выполняются, ошибки очищаются. Тесты проверили отсутствие пароля в SQLite/WAL/бэкапах, файлах проекта, журналах, всех ответах API, событиях заданий, stdout и argv всех процессов (/proc/*/cmdline во время задания).
- **Политика (lib/policy.js)**, единая точка решений с id правила в журнале:
  - shell запрещён всегда;
  - bash, webfetch, websearch, task, skill, question, external_directory и doom_loop запрещены;
  - edit/write разрешены только внутри папки версии проекта, после realpath с проверкой symlink;
  - агенту запрещено создавать или перезаписывать .blend/.png/.glb/.fbx;
  - удаление версии и публикация требуют подтверждения; сгенерированный bpy требует подтверждения (режим пока не включён в UI).
- **Защита в глубину:** перед каждым заданием студия читает `GET /config` сервера и **блокирует задание**, если `bash/webfetch/external_directory` ≠ `deny` или `edit` ≠ `ask`. Поэтому каждое изменение файла приходит к студии как permission-запрос. Студия отвечает только `once`/`reject`, никогда `always`. После работы агента файлы на диске проверяются ещё раз; лишние файлы игнорируются и попадают в журнал.
- **LLM не пишет код Blender:** агент выбирает только значения по строгой схеме (`lib/scene-params.js`: enum/диапазоны, неизвестные поля запрещены), а Blender исполняет проверенный шаблон `blender/templates/scene_basic.py`. Пути шаблон дополнительно ограничивает папкой версии.
- **Blender** запускается через `spawn` без shell, argv содержит только пути, окружение минимальное (без переменных студии). Есть таймаут, отмена (SIGTERM→SIGKILL группы процессов), а после перезапуска сиротские процессы убиваются по сохранённому pid. Бинарник должен называться `blender`/`Blender`, путь только абсолютный.
- **Файлы проекта** отдаются только авторизованным, без traversal (realpath внутри папки версии); не-PNG отдаются как attachment.
- Тесты: `npm run test:policy` (46), `npm run test:3d` (реальный opencode serve 1.19.3 + реальный Blender 5.2.2).

**Остаточные риски 1.2.0:**
- Сервер OpenCode запускает пользователь, вне песочницы студии. Если запустить его с другой политикой, студия откажется работать, но сам сервер остаётся доступен другим клиентам с паролем.
- Чтение файлов (`read`) агентом разрешено конфигом сервера (allow), в том числе вне папки, если это не перехватит `external_directory` (deny). Проверено только поведением OpenCode 1.19.3.
- Мок-LLM в тестах не повторяет реальных ошибок qwen2.5-coder:7b.
- Модели Ollama не изолированы от сети (как и раньше).
