# Аудит безопасности MOONKATTY AI STUDIO (ветка feat/macos-app, версия 1.1.1)

Дата: 20.10.2026. Аудит выполнен по исходному коду и автоматическими тестами на Linux. Это **не** внешний пентест и **не** гарантия безопасности: приложение не проверялось на реальном Mac, сторонний аудит не проводился.

## Найденные уязвимости и статус

| # | Серьёзность | Проблема | Статус |
|---|---|---|---|
| 1 | Высокая | **DNS rebinding**: сервер принимал любой заголовок Host. Сайт злоумышленника, «перепривязанный» на 127.0.0.1, мог вызывать неаутентифицированные маршруты — в т.ч. `POST /api/auth/setup` (создать администратора до Игоря на свежей установке) и подбор пароля. | Исправлено: allowlist Host (`127.0.0.1:порт`, `localhost:порт`, `[::1]:порт` + явно заданные имена Tailscale `*.ts.net`), иначе 421. |
| 2 | Высокая | **Electron 41** вне поддержки (поддерживаются 3 последние major: 44, 43, 42). | Исправлено: Electron 44.9.1 (последняя на дату аудита), версия закреплена точно. |
| 3 | Средняя | **CSRF с других localhost-портов**: SameSite=Strict не защищает от «same-site» страниц (любой порт на 127.0.0.1/localhost); `POST /api/files/upload` принимал `text/plain`. | Исправлено: для изменяющих запросов обязателен заголовок `X-Studio-Request: 1` + проверка Origin и Sec-Fetch-Site; CORS не выдаётся. |
| 4 | Средняя | **Обход утверждения OpenCode**: поле `codeApproved` можно было выставить общим `PUT /api/tasks/:id`. | Исправлено: серверные поля (`codeApproved*`, `history`, `actionLog` и др.) вырезаются из общих CRUD-запросов; одобрение — только `POST /api/tasks/:id/approve-code`; изменение типа задачи сбрасывает одобрение. |
| 5 | Средняя | **OpenCode «в песочнице»** на деле был просто отдельной папкой: процесс мог читать/писать всё, что доступно пользователю. | Исправлено частично: OpenCode **выключен по умолчанию**; включается только вручную (`enableOpenCode: true` в `desktop.json` / `STUDIO_OPENCODE=1`). ## Модель безопасности (кратко)

- **Сеть**: сервер слушает только 127.0.0.1. Удалённый доступ — только через `tailscale serve`, имя `*.ts.net` нужно явно добавить в `allowedHosts` в `desktop.json`.
- **Аутентификация**: пароль (scrypt) → cookie сессии HttpOnly, SameSite=Strict; вход ограничен 5 неудачными попытками в минуту. Окно приложения входит по локальному токену (`app-token`, файл 0600): он передаётся только в заголовке из main-процесса Electron к 127.0.0.1, недоступен JS страницы; принимается только с loopback и без чужого Origin.
- **Остаточный риск, локальные процессы**: любая программа, запущенная от вашего пользователя macOS, может прочитать `app-token`, базу и ключ (как и любые данные пользователя). Keychain тоже не защищает от процессов того же пользователя, которым вы разрешили доступ. Защита от вредоносного ПО на вашем Mac этим приложением не обеспечивается.
- **Агенты**: только argv-вызовы (`spawn` без shell), фиксированные пути (`/usr/bin/security`, `/bin/launchctl`, `/usr/bin/sandbox-exec`); ответы LLM только сохраняются как черновики на утверждение и никогда не исполняются. Агенты не меняют системные настройки и не читают секреты. Публикация и ответы — только после утверждения человеком.
- **Prompt injection**: текст новостей/комментариев может повлиять на черновик LLM, но не на действия: план Director создаёт только обычные задачи (не задачи кода), а задачи кода требуют отдельного одобрения и выключены по умолчанию.
- **Обновления**: только HTTPS-запрос к GitHub API закреплённого репозитория; предложение показывается, только если в релизе есть zip и `.sha256`, и они совпадают с digest, который вычисляет сам GitHub. Ничего не скачивается и не устанавливается автоматически: архив скачивается в браузере (получает карантин Gatekeeper). Это защищает от повреждения, но **не** от компрометации самого репозитория/аккаунта GitHub — для этого нужна подпись Developer ID.

## Оставшиеся риски (прямо)

1. Сборка **не подписана Developer ID и не нотаризована**; ad-hoc подпись ничего не говорит о происхождении. Проверка подлинности — только сверка SHA-256 и (лучше) сборка из исходников самостоятельно.
2. **Ничего не проверено на macOS**: Gatekeeper, launchd, Keychain, sandbox-exec, fuses в работе, шифрование cookies. См. `docs/MAC_TEST_CHECKLIST.md`.
3. Код сервера лежит в `app.asar.unpacked` — проверка целостности ASAR его **не покрывает**; ad-hoc подпись покрывает (`codesign --verify`), но только если её проверяют.
4. `sandbox-exec` объявлен Apple устаревшим; профиль OpenCode не тестировался; сеть для OpenCode открыта (возможна утечка содержимого папки задачи).
5. `/api/health` без аутентификации раскрывает pid/версию/источник ключа (только для 127.0.0.1 и разрешённых хостов).
6. Сторонний JS панели не используется, но страницы Graph API отдают изображения по https — CSP разрешает `img-src https:`.
7. XSS в панели проверен выборочно (поиск неэкранированных вставок), не формально.
