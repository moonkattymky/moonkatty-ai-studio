Проверено 21 октября 2026 на Linux, Node v22.23.3, драйвер `node:sqlite`. Это не Mac mini. `better-sqlite3` в этой среде нет (`MODULE_NOT_FOUND`). Файл `MOONKATTY_MASTER.blend` не открывался и не создавался. Ветки Studio 3, main и `feat/v1.2.0` не редактировались. `server.js` не менялся.

Код сверки журнала: `feat/studio-intelligence` @ `3931864`. Журнал Studio 3, с которым сверялись: `feat/studio-operations` @ `e9a46bf`. Схема main: `e87bd32`. Схема `feat/v1.2.0`: `a3fd83a` (внутри него v1.2.1 `42d3fd5` и `video_render` `a991e93`). Откат файла — только PR #3, ветка `cursor/studio-server-integration-c51e`. Ветку `feat/v1.2.2-test-isolated` не открывали и не меняли.

## 1. Что реально работает

На прогнанных тестах работает следующее.

Три пространства `moonkatty_news`, `moonkatty_project` и `moonkatty_shared` лежат в одном файле `data/studio.db`. Новости не читают проект, проект не читает новости, общее читают оба. Запись в общее — у владельца и у агентов `director` и `design3d`, как в грантах. Роль редактора в схеме есть и в коде выключена: итоговое утверждение ставит владелец, `auto_execute` остаётся 0, `executed` остаётся false.

Реестр `MOONKATTY_MASTER_CHARACTER` хранит версию, SHA-256, статус утверждения, права на референсы и связь с `voiceProfileId`. Он не создаёт файл `.blend` и не вызывает Blender. Постоянный id карточки — `MOONKATTY_MASTER_CHARACTER` в `moonkatty_shared`.

История активов, использований и утверждений пишется в таблицы `si_*` того же файла. Короткий журнал панели (потолок 2000) получает одну строку, если хост передал свою функцию `log`. Второй базы нет. Второй журнал денег нет: `recordCost` отвечает `NOT_IMPLEMENTED`, в `si_cost_entries` новые строки не пишутся. Чтение идёт в `createLedger` из `lib/ops/ledger.js` коммита `e9a46bf` (файл взят через `git show` во временный каталог). Сумма-строка, дата `YYYY-MM-DD` и `proof` объектом проходят в отчёт числом. Факт 16.50 USD расхода, оценка 1 USD и прогноз 9 USD не смешиваются. `moonkatty_shared` узнаётся. `moonkatty_project:nope` становится `unassigned`, исходная строка сохраняется. `resolveProject` экспортируется синхронно из `studio-intelligence/src/projects.js` и не возвращает Promise.

Миграция на базе, собранной SQL `items`/`meta` из `server.js` ветки main, и на базе, которую открыли `lib/db.js` и `lib/jobs.js` с `feat/v1.2.0` @ `a3fd83a`, сохраняет прежние строки `items`, `meta`, `jobs` и `job_events` и добавляет `si_*`. Строка `video_render` — это запись в `jobs` (`input`, `idempotency_key`), отдельной таблицы нет, и она тоже остаётся. Откат — подмена файла, не обратный SQL. После порчи `--apply` возвращает задачу, meta, задание `jobs` и эту строку рендера. JSON-файл `backup-*.json` при этом не меняется. Скрипты отката есть только в PR #3.

## 2. Что проверено только тестами

Всё из пункта 1 проверено автоматическими тестами `node:test` в этой виртуальной машине. Живой процесс `server.js` не запускался. Запрос `GET /api/ops/ledger` по сети с токеном приложения не отправлялся. Флаг `STUDIO_OPS_MONEY=1` здесь не включался: их `listEntries` вызывался напрямую из временной копии `ledger.js`, без `lib/ops/index.js` и без их сервера.

База main собрана тем же SQL, что в `server.js` main, но через `node:sqlite`, потому что `better-sqlite3` не установлен. База `feat/v1.2.0` собрана их `lib/db.js` и `lib/jobs.js` из временной копии коммита `a3fd83a`, тоже на `node:sqlite`. Это не запущенное приложение 1.2.1 и не файл `data/studio.db` с Mac.

Копия базы для отката снималась после закрытия соединения. Это `copyFileSync`, не онлайн-backup SQLite. Строки Cost Controller (`includeCostController`, по умолчанию у них включено) в прогон не подмешивались: в `createLedger` объект `costs` не передавался.

Поиск FTS, права, мягкое удаление актива, блокировка жёсткого удаления мастер-id и записи с ссылкой на задачу, голос, версии сценария и журнал поправок тоже закрыты тестами. Публикации и платного TTS эти тесты не выполняют.

## 3. Что на Mac не проверено

Не проверялось на Mac mini и вообще на macOS:

- скрипт раскладки по настоящему `~/Documents/MOONKATTY-ASSETS` (тест ходит во временный каталог);
- наличие и хеш настоящего `MOONKATTY_MASTER.blend` и картинок в каталоге `references`;
- драйвер `better-sqlite3`, которым `server.js` на main открывает базу;
- приложение Electron и сборка, которую ставят на Mac;
- Blender и любой `.blend`;
- живой `GET /api/ops/ledger` с токеном приложения и включённым `STUDIO_OPS_MONEY`;
- копия файла, пока сервер держит `data/studio.db` открытым.

## 5. Известные ошибки и дыры

Исправлено в `3931864` и заново прогнано: раньше адаптер ждал число и дату ISO, а их журнал отдаёт строку суммы и `YYYY-MM-DD`, из-за чего дневной отчёт падал или обнулялся. `resolveProject` не был экспортом модуля, поэтому их загрузчик его не видел: голый `moonkatty_shared` становился `unassigned`, а неизвестный id вида `пространство:slug` их запасной разбор считал известным. Теперь экспорт есть. Если их процесс не может сделать `require` на `studio-intelligence/src/projects.js`, остаётся их запасной разбор — это уже их процесс без наших файлов.

Что по-прежнему не подключено, и это не спрятано:

- `server.js` этот модуль не вызывает. `attach` есть только в PR #3 и сам маршруты не вешает. Пока хост не передаст открытую базу и `listEntries`, панель память не использует.
- Без `STUDIO_OPS_MONEY=1` их `listEntries` равен `null`. Отчёт тогда честно ставит `ledger.source = 'none'` и нули, а не выдуманные суммы.
- JSON-копии панели (`backup-*.json`) таблицы `si_*` не содержат. Восстановить по ним память нельзя.
- Обратного SQL нет. Без файловой копии из PR #3 снять миграцию нечем. Самих скриптов отката в PR #1 нет.
- `brand.check` и `workflow.run` по-прежнему `NOT_IMPLEMENTED`. Ничего не публикуется само.
- Копия базы — побайтовое копирование закрытого файла. На открытой базе работающего сервера она не проверялась и может снять несогласованный WAL.
- Реестр персонажа не видит файл, которого нет. Хеш мастер-модели на этой машине не из чего считать.

## 7. Установка

На Mac это ставить как часть текущей сборки нельзя: сборка этот код не содержит, а `server.js` к нему не подключён.

Если владелец отдельно выпишет ветку и захочет только посмотреть пути модели, из корня репозитория, без `--apply`:

```bash
node studio-intelligence/scripts/character-layout.js
```

Скрипт по умолчанию ничего не создаёт и ничего не переносит. Печатает найденные `MOONKATTY_MASTER.blend` и картинки в каталогах с именем `references`. Эти пути передаются основной студии. `--apply` создаёт только недостающие каталоги под `~/Documents/MOONKATTY-ASSETS/CHARACTERS/MASTER/` и не перезаписывает уже лежащие файлы. Этот прогон на Mac так не запускался.

Память в панели сама не появится. Нужны влитый код и правка хоста, которая сюда сознательно не входила: открыть тот же `data/studio.db` и передать `listEntries` их журнала. Пока этого нет, установка ветки на диск приложение не включает.

## 8. Откат

Обратного SQL нет. Откат — замена файла `data/studio.db` копией.

Скрипты только в PR #3. Сначала отчёт, без записи:

```bash
node studio-intelligence/scripts/backup-db.js --db data/studio.db
node studio-intelligence/scripts/rollback-db.js --db data/studio.db --from data/backups/studio-db-<штамп>.sqlite
```

Запись — с `--apply`. Откат требует `--db` и `--from`. Перед копией назад скрипт удаляет рядом лежащие `-wal` и `-shm`, чтобы старый журнал SQLite не накатился поверх восстановленного файла. JSON-копии `backup-*.json` он не читает и не удаляет. Хранится до 14 файлов с префиксом `studio-db-`.

Проверено тестами PR #3 на закрытой базе: копия до миграции, порча `items` и `jobs`, сухой прогон порчу не снимает, `--apply` возвращает задачу main, задачу и строку `video_render` из `a3fd83a`, строку `meta` и события `job_events`. Таблиц `si_*` после такого отката нет — их не было в копии. На работающем сервере Mac это не запускалось.

В PR #1 этих скриптов нет. JSON-бэкап панели память не откатывает.

## 9. Вердикт готовности

К установке на Mac в составе текущей сборки не готово.

Сборка `feat/v1.2.0` @ `a3fd83a` (в `package.json` это уже 1.2.1) этот модуль не содержит, пока PR #1 не влит. Даже после влития панель его не вызовет, пока хост не соединит базу и журнал. Этот аудит `server.js` не трогал. Ветку `feat/v1.2.2-test-isolated` не трогали.

Сама память на Linux тестами закрыта: пространства, реестр без генерации модели, история активов и утверждений в том же файле, без второго журнала денег, миграция поверх main и поверх `a3fd83a` данные не стирает, откат файлом в PR #3 возвращает проверенные строки, включая `video_render`. Это не проверка Mac, не проверка живого сервера и не разрешение публиковать или двигать `MOONKATTY_MASTER.blend`.
