# План подключения к server.js

`server.js` этой веткой не меняется. Ниже — то, что хост вызывает сам, когда файл можно будет править.

## Шаги

1. Открыть ту же базу: `openStudioIntelligence({ db, auditLog: log, ledger })`.
2. `log` — существующая функция журнала панели. Она сама обрезает коллекцию `logs` до 2000 строк.
3. `ledger` — объект с `listEntries` из `lib/ops/ledger` (`feat/studio-operations` @ `e9a46bf`). Пока функция не передана, отчёт показывает, что журнал денег не подключён. `server.js` этим модулем сам не дополняется.
4. Сессию по-прежнему проверяет сервер. В модуль уходит уже проверенный `{ user, exp }`.
5. Задачи в очередь панели кладёт хост из `runtime.handoff`. Пространство `moonkatty_shared` в очередь не ставится.
6. Резервная копия JSON панели не содержит `si_*`. Рядом нужен файл `studio.db` в `data/backups`. Скрипт копии и отката вынесен в отдельный черновик подключения, чтобы diff к `main` не смешивался с памятью.

## Контракты соседних студий

| Кто | Что читает и пишет у нас | Чего мы не делаем |
|---|---|---|
| Основная студия | реестр версии, `voiceProfileId`, журнал утверждений | не строим риг и не пишем `.blend` |
| Студия 2 | задаёт профиль голоса, читает права и повтор файла | не зовём ffmpeg и не качаем стоки |
| Студия 3 | `resolveProject`, чтение их журнала в дневной отчёт | не ведём второй журнал денег и не рисуем экран телефона |
| Студия 4 | читает права, пишет находку проверки и черновик поправки | процедуру выпуска не исполняем |

Подробности: `STUDIO.md`, `STUDIO-2.md`, `STUDIO-3.md`, `STUDIO-4.md` в этом каталоге.
