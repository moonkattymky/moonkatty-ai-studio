# Риски и ограничения

## Ограничения сделанного

1. Журнал утверждений и карточки активов пишутся. `decide`, регистрация бренда и `prepareFacialUse` возвращают `executed: false`. В базе `auto_execute` всегда 0. `workflow.run` и `brand.check` по-прежнему `NOT_IMPLEMENTED`. Запись «утверждено» не публикует выпуск и не подменяет кота: это должен уважать хост, когда его подключат.
2. Библиотека не встроена в `server.js`. Пока хост сам не вызовет `openStudioIntelligence` и не применит патчи зависимостей до `runner.tick()`, исполнитель о зависимостях не узнает.
3. `runner.stop` возвращает задачу в `queued`. Отмена доходит до `cancelled`, только если хост после остановки запишет `plan.then`. Иначе задача снова уйдёт в работу.
4. Между `approve-code` (ветка №1) и следующим `reconcileDependencies` есть окно: одобренная задача кода на один тик может стать `queued` при невыполненных зависимостях, если хост сначала дернёт исполнитель. Порядок в `INTEGRATION.md`: сначала патчи зависимостей, потом `runner.tick()`.
5. Права действуют на таблицы `si_*`. Общий CRUD `items` по-прежнему доступен вошедшему администратору. Отдельного входа для агента нет, поэтому сегодня агент не ходит в HTTP сам. Когда у агента появится инструмент записи в `tasks`, его надо провести через адаптер, а не через общий `PUT`.
6. `principalFromSession` доверяет хосту. Кто передал объект `{ user }`, тот и стал владельцем. Это отображение сессии, не проверка пароля.
7. Поиск не понимает смысл, только совпадение слов и префикс (`кот*` находит `кота`). Русского стеммера нет: «котом» и «кот» без общего префикса могут разъехаться. Ответ собирается только из цитат; если цитат нет, модуль так и пишет, а не достраивает текст.
8. Слово `access_token` в документе выкидывает фрагмент из индекса (`SECRET_REJECTED` / `skipped: secret`). Так задумано, но описание Meta API может не попасть в поиск.
9. В панели один администратор. Роль `owner` — это он. Отдельных людей с правом утверждать, но без права читать всё, схема не различает.
10. `design3d` в продукте выключен, кода Blender нет. Сценарий `studio3d` описывает шаги и не рендерит.
11. Медиа-ветка хранит сюжеты и `mediaLicense` в своём JSON. Эта библиотека его не читает и не синхронизирует сама. Пока ролик явно не положен в `si_assets`, поиск по памяти и проверка прав его не увидят. Две записи об одном файле разъедутся, если медиа-ветка не вызовет `register`.
12. Отчёт `reports.daily` не подменяет `core.buildReport` и `/api/mobile/summary`. Пока телефон читает только коллекции панели, цифры памяти на нём не появятся. `costs.totalUsd` — это только фактический расход в USD из журнала Studio 3. Прогноз туда не входит. Ноль значит «фактических строк за период нет», а не «биллинг подтвердил ноль». Пока `listEntries` не передан, `ledger.source` равен `none`.
13. `design3d` видит утверждённую мастер-модель, но не пишет использование в новостях и не читает чужое аудио. Мимику в память кладёт агент с записью в `moonkatty_news` (сейчас это `video`).
14. Замер нагрузки сделан на Linux-VM, не на Mac mini. Цифры — в `LOAD.md`. На Apple Silicon порядок тот же, точные миллисекунды будут другими.
15. `node:sqlite` в Node 22 помечен как экспериментальный. На установленной панели предпочтителен `better-sqlite3` или `lib/db.js`.

## Что сознательно не делается

- Второй цикл исполнения задач, свой Ollama/OpenCode, свой ffmpeg.
- Вторая база и свой список пользователей.
- Автоматическая подмена оригинального кота, автопубликация, автозапуск шага с утверждением владельца.
- Эмбеддинги и отдельный векторный индекс.

## Ответы владельца, уже принятые в коде

1. Три пространства: новости, проект и общее. Новости и проект не смешиваются. Общее читают оба по правам.
2. Итог по публикации, мастер-модели, изменению проекта и расходу ставит только владелец. Роль редактора описана и выключена.
3. Файлы кота основная студия хранит сама. Целевой каталог на Mac mini: `~/Documents/MOONKATTY-ASSETS/CHARACTERS/MASTER/`. В git файла `MOONKATTY_MASTER.blend` нет. Реестр памяти хранит хеш и путь, файл не создаёт.
4. `server.js` этой веткой не меняется. Подключение — отдельный черновик.
5. Эмбеддинги остаются выключенными.
6. Платных вызовов нет. Публикация без утверждения Игоря не выполняется: у решения `executed: false`.
