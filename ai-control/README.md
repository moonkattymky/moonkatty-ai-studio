# MOONKATTY AI CONTROL — этап 2 (реальные данные студии, только чтение)

Личный пульт владельца (Игорь) для наблюдения за **MOONKATTY AI STUDIO** с iPhone.
Этап 2 подключает те же 12 экранов к **реальным данным студии — только чтение**. Дизайн и раскладка экранов
не менялись: заменены источники данных и добавлены метки состояния данных.

* **LIVE** (по умолчанию) — данные из существующего API студии через локальный read-only прокси `server.mjs`.
  У каждого значения метка: **ПОДТВЕРЖДЕНО** (реальный источник), **ОЦЕНКА** (прогноз/начисление, студия сама
  так помечает), **DEMO** (студия отдаёт демо/mock), **НЕТ ДАННЫХ** (источника нет или он пуст).
  Все действия (одобрить, пауза, публикация, бэкап, подключение…) выключены с подписью
  «Управление — после отдельного разрешения».
* **DEMO** — прототип этапа 1 без единого запроса к студии (`AIC_MODE=demo`), работает офлайн; постоянный
  значок «DEMO» виден только в этом режиме.

Подробности (карта эндпоинтов, метки, пробелы, модель безопасности): [`docs/STAGE2_INTEGRATION.md`](docs/STAGE2_INTEGRATION.md).

## Запуск на Mac mini (против тестового экземпляра 8687)

Нужен Node.js 18+ (проверено на Node 22). Зависимостей у сервера нет.

1. Запустите **тестовую** студию MOONKATTY AI STUDIO TEST как обычно (она слушает `127.0.0.1:8687`) и убедитесь,
   что у неё задан пароль владельца (первый вход в панели студии или `STUDIO_ADMIN_PASSWORD` при первом запуске).
2. Запустите пульт:

```bash
cd moonkatty-ai-studio
node ai-control/server.mjs
# → MOONKATTY AI CONTROL (LIVE → Studio http://127.0.0.1:8687, только чтение) → http://127.0.0.1:8697/  (local only)
```

3. Откройте в Safari на Mac mini <http://127.0.0.1:8697/> → экран «Вход владельца» → логин и пароль владельца
   **тестовой** студии (те же, что в панели студии; по умолчанию логин `igor`) → «Войти».
4. «Выйти» — внизу экрана «Ещё». Сессия также закрывается сама после **15 минут без действий** (и не живёт дольше 12 ч).

### Порт

**8697** (раньше 8690). 8690 оказался занят: это Node API (TLS) тестовой сборки студии (`lib/studio-config.js`,
`docs/MAC_MINI_v1.3.0-test.md`). Сервер отказывается стартовать на 8787, 8687, 8690, 8790, 8791, 8795, 4096, 4097.
Другой порт: `PORT=8698 node ai-control/server.mjs`.

### Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `AIC_MODE` | `live` | `demo` — прототип этапа 1, без прокси и без запросов к студии (или флаг `--demo`) |
| `STUDIO_URL` | `http://127.0.0.1:8687` | адрес студии; только `http://127.0.0.1:<порт>` (loopback, без логина/пути в URL) |
| `AIC_ALLOW_PROD` | — | `1` обязателен, если `STUDIO_URL` указывает на **прод 8787** (иначе отказ запуска) |
| `PORT` | `8697` | порт пульта (только 127.0.0.1) |
| `AIC_IDLE_MIN` | `15` | таймаут сессии без действий, минут |
| `AIC_COOKIE_SECURE` | — | `1` — флаг `Secure` у cookie (когда пульт отдаётся по HTTPS, этап 3) |
| `AIC_QUIET` | — | `1` — не писать журнал запросов в stdout |

Прод (v1.1.2, 8787) — **только** явно: `STUDIO_URL=http://127.0.0.1:8787 AIC_ALLOW_PROD=1 node ai-control/server.mjs`.

### Что важно знать

* Сервер слушает **только 127.0.0.1**. Никакого Tailscale, LAN или публичного доступа на этапе 2; с iPhone по сети
  пульт намеренно не открывается (этап 3). Для вида «как на iPhone»: Safari → «Разработка» → «Адаптивный дизайн».
* Пароль владельца **один раз** передаётся в существующий `POST /api/auth/login` студии и нигде не сохраняется.
  Сессия студии (`mk_session`) остаётся внутри прокси (в памяти); браузер получает только свою cookie `aic_sid`
  (`HttpOnly; SameSite=Strict; Path=/`). Перезапуск пульта = все входы сброшены.
* «Выйти» (и истечение сессии) вызывает `POST /api/auth/logout` студии. **Побочный эффект студии:** её logout
  также выключает автовход десктоп-приложения студии до следующего входа по паролю (так устроен `server.js`).
* К студии уходят только GET-запросы из белого списка; всё остальное прокси отклоняет (405/403).
* При старте сервер собирает `ai-control/dist/` из `ai-control/src/` (`--no-build` — отдать готовую сборку).

## Что внутри

```

  server.mjs            127.0.0.1: статика + read-only прокси к студии (allowlist GET, вход/выход, сессии в памяти)

  src/index.html        оболочка, строгий CSP (без inline-скриптов/стилей и eval), meta для iOS

  src/sw.js             service worker: кэширует ТОЛЬКО статику; /api/* и /aic/* — никогда
  src/js/live-data.js   этап 2: GET-клиент + адаптеры «ответ студии → форма demo-data.js» + метки данных
  src/js/demo-data.js   DEMO-данные этапа 1 (только режим DEMO)
  src/js/i18n.js        словарь RU (по умолчанию) / EN (Настройки → Внешний вид)
  src/js/app.js         hash-роутер, экраны, шторки, тосты, экран входа, режимы DEMO/LIVE
  src/js/icons.js, charts.js, css/app.css, img/, icons/   как на этапе 1
  docs/STAGE2_INTEGRATION.md   карта эндпоинтов, метки, пробелы, предложения, безопасность
  test/                 Playwright DEMO (этап 1, iPhone 16 Pro 402×874 @3x, iOS 18 UA, WebKit + Chromium)
  test/live/            Playwright LIVE против настоящих тестовых студий (temp БД, тестовый пароль)
```

## Что такое DEMO на этапе 1

* Данные — только из `src/js/demo-data.js`. Сетевых запросов, кроме статических файлов того же origin, нет.
* «Одобрить» / «На доработку», пауза агента, прочтение уведомлений, идеи, эксперименты, тумблеры,
  язык, валюта — меняют **только локальное DEMO-состояние** в `localStorage` этого устройства
  (сброс: Настройки → О приложении → «Сбросить DEMO-состояние»). Кнопки подписаны «DEMO», тосты — «DEMO: …».
* Всё, что пока не может работать, **выключено** и подписано «Будет доступно на этапе 2»
  (или «…на этапе 3», если это вход владельца / выход):
  новый запрос агентам, создание агента/задачи, «Дать задачу», воспроизведение видео, публикация в соцсети,
  подключение интеграций, перезапуск студии и журнал Mac mini, сценарии/темы новостей, экспорт отчёта,
  добавление виджета/расхода, документы, резервные копии, поддержка, Face ID / passkey, «Выйти».

## Тесты

```bash
cd ai-control
npm install && npx playwright install webkit chromium
npm test                    # DEMO-режим (этап 1): экраны, sweep, PWA/SW, CSP, поведение — порт 8697, AIC_MODE=demo
sh test/live/run.sh         # LIVE: 2 временные тестовые студии (код integ d1adf4d в отдельном worktree) + 3 прокси
                            # в изолированном сетевом namespace (/workspace/mk-iso.sh); скриншоты → /workspace/out/ai-control/stage2/
STUDIO_DIR=/путь/к/worktree sh test/live/run.sh   # другой checkout студии
```

LIVE-тесты: вход/выход/таймаут; 401 без входа; 405 на не-GET, 403 вне белого списка, 421 на чужой Host, 403 на
вход без `X-AIC-Request`/с чужим Origin; каждый из 12 экранов — реальные значения или «НЕТ ДАННЫХ», метки, нет ошибок
консоли/CSP/внешних запросов и только GET; совпадение с ответами студии; финансы (подтверждено / оценка / DEMO
раздельно, DEMO и оценки никогда не помечены «ПОДТВЕРЖДЕНО»); нет секретов в ответах, журналах, localStorage,
sessionStorage, cookie и кэше; SW не кэширует `/api`/`/aic`; CSP; sweep всех кнопок (действия выключены с подписью).
Пароль в тестах — тестовый, только для временных БД (как в `scripts/security-test.mjs` студии), не настоящий.
