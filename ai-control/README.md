# MOONKATTY AI CONTROL — этап 1 (прототип PWA)

Личный пульт владельца (Игорь) для наблюдения за **MOONKATTY AI STUDIO** с iPhone.
Этап 1 — это **прототип на DEMO-данных**: ни одного запроса к реальным аккаунтам, API или внешним сайтам.

> ⚠️ **Все цифры, списки, статусы и финансы — DEMO.** На каждом экране висит постоянный значок «DEMO»,
> рядом с итогами (выручка, доходы, просмотры) стоит чип «DEMO».

## Запуск на Mac mini

Нужен Node.js 18+ (проверено на Node 22). Ничего устанавливать не нужно — у приложения нет зависимостей.

```bash
cd moonkatty-ai-studio
node ai-control/server.mjs
# → MOONKATTY AI CONTROL (DEMO) → http://127.0.0.1:8690/  (local only)
```

* Сервер слушает **только 127.0.0.1** (порт 8690; другой порт: `PORT=8691 node ai-control/server.mjs`).
  Порты 8787, 8687, 4096, 4097 заняты другими сервисами MOONKATTY и запрещены.
* При старте сервер собирает статическую сборку `ai-control/dist/` из `ai-control/src/`
  (`node ai-control/build.mjs` делает то же самое отдельно; `--no-build` — отдать существующую сборку).
* Сервер отдаёт только статические файлы с заголовками безопасности (CSP, `X-Frame-Options: DENY`,
  `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, COOP/CORP). `/api/*` всегда отвечает 404 —
  API на этапе 1 нет.
* Открыть в Safari на самом Mac mini: <http://127.0.0.1:8690/>. С iPhone по сети на этапе 1 **не открывается
  намеренно** (только localhost); доступ с телефона — этап 3 (Tailscale HTTPS).
  Для просмотра «как на iPhone» — Safari → «Разработка» → «Адаптивный дизайн» → iPhone 15 Pro.

## Что внутри

```
ai-control/
  server.mjs            локальный статический сервер (127.0.0.1, заголовки безопасности)
  build.mjs             статическая сборка src → dist, версия кэша SW = хэш содержимого
  src/index.html        оболочка, строгий CSP (без inline-скриптов/стилей и eval), meta для iOS
  src/manifest.webmanifest   «MOONKATTY AI CONTROL», standalone, иконки 180/192/512 (+maskable)
  src/sw.js             service worker: кэширует ТОЛЬКО статику, версионированный кэш, /api/* никогда
  src/js/demo-data.js   ВСЕ DEMO-данные в одном файле (на этапе 2 заменяется read-only API)
  src/js/i18n.js        словарь RU (по умолчанию) / EN (переключатель в Настройки → Внешний вид)
  src/js/app.js         hash-роутер, экраны, шторки, тосты, локальное DEMO-состояние
  src/js/icons.js       локальный набор SVG-иконок (без CDN и веб-шрифтов)
  src/js/charts.js      маленькие SVG-графики (линейный, столбчатый, спарклайны)
  src/css/app.css       стиль по утверждённому макету: космос, синий/фиолетовый, золото
  src/img/              кадры из утверждённого макета + изображения из public/img
  src/icons/            иконки PWA и apple-touch-icon (tools/make-icons.mjs)
  test/                 Playwright (iPhone 15 Pro): экраны, «sweep» всех кнопок, PWA/SW, CSP, поведение
  tools/compose.py      листы сравнения «макет ↔ реализация» и общий лист 6×2
```

Без фреймворков: чистый JS (ES-модули) и CSS, вся сборка ~1 МБ (в основном картинки).

## Что такое DEMO на этапе 1

* Данные — только из `src/js/demo-data.js`. Сетевых запросов, кроме статических файлов того же origin, нет.
* «Одобрить» / «На доработку», пауза агента, прочтение уведомлений, идеи, эксперименты, тумблеры,
  язык, валюта — меняют **только локальное DEMO-состояние** в `localStorage` этого устройства
  (сброс: Настройки → О приложении → «Сбросить DEMO-состояние»). Кнопки подписаны «DEMO», тосты — «DEMO: …».
* Всё, что пока не может работать, **выключено** и подписано «Будет доступно на этапе 2»
  (или «…на этапе 3», если это вход владельца / выход):
  новый запрос агентам, создание агента/задачи, «Дать задачу», воспроизведение видео, публикация в соцсети,
  подключение интеграций, перезапуск студии и журнал Mac mini, сценарии/темы новостей, экспорт отчёта,
  добавление виджета/расхода, документы, резервные копии, поддержка, Face ID / passkey, «Выйти».

## Этап 2 — реальные данные, только чтение

* Небольшой read-only API на Mac mini (`/api/v1/...`: агенты, задачи, контент, аналитика, финансы, игры,
  новости, соцсети, уведомления, устройства). Форматы ответов = форматы объектов в `demo-data.js`,
  поэтому замена — один модуль-адаптер вместо `demo-data.js`.
* Service worker уже сейчас не кэширует `/api/*` — свежие данные всегда идут из сети.
* Включатся: просмотр видео-превью, статусы Mac mini/устройств, список интеграций, история уведомлений.
* Действия «Одобрить / На доработку» по-прежнему локальные, пока не появится аутентификация (этап 3).

## Этап 3 — доступ с iPhone и вход владельца

* Доступ с телефона через **Tailscale HTTPS** (`*.ts.net`, сертификат Tailscale), без публикации в интернет.
* Вход владельца: passkey / Face ID (WebAuthn), короткие сессии, защита от CSRF.
* Только после этого — реальные действия (одобрение, отправка на доработку, публикация) с журналом аудита.

## Тесты

```bash
cd ai-control
npm install                      # только dev-зависимость @playwright/test
npx playwright install webkit chromium
npm test                         # Playwright, профиль iPhone 15 Pro (WebKit и Chromium)
node test/screenshots.mjs        # PNG всех 12 экранов 393×852 @3x → /workspace/out/ai-control/screens
python3 tools/compose.py <макет.png> /workspace/out/ai-control   # листы сравнения + all-12.png
```

Тесты проверяют: 12 экранов и все подэкраны открываются; на каждом есть «DEMO»; нет ошибок консоли
и нарушений CSP; нет запросов на другие origin; **sweep** нажимает каждую кнопку/ссылку/[role=button] и
требует навигацию, изменение состояния или тост — либо `disabled` с подписью про этап 2/3; манифест и
иконки корректны; SW регистрируется, работает офлайн и не кэширует `/api/*`; фильтры фильтруют;
RU/EN переключается; учитывается `prefers-reduced-motion`.
