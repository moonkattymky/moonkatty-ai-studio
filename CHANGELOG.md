## 1.2.3-test — исправления по повторной проверке Studio 4 (feat/quality-automation bfa720a, 2026-10-21)
Та же изоляция, что у 1.2.2-test: bundle id `com.moonkatty.aistudio.test`, Keychain `MOONKATTY AI STUDIO.test`, порты 8687/4097, launchd `com.moonkatty.aistudio.test.server`.
- **HMAC-ключ печати публикаций перенесён в Keychain.** Он хранится в сервисе текущей сборки, учётная запись `publish-seal-key`, и записывается через stdin `security -i`, а не через argv. В `studio.db` ключа больше нет: копия из v1.2.2-test (`meta.publishSealKey`) переносится в Keychain и удаляется из БД (`secure_delete`, `VACUUM`). Если Keychain недоступна, ключа нет и публикация запрещена. Ключ создаётся только при первой настоящей публикации.
- **Строки «опубликовано» без действительной печати.** К ним относятся данные v1.1.x–v1.2.2, прямые записи в БД, печать чужим ключом и подменённый `externalId`. При каждом запуске они переводятся в `pending_approval`, а прежние значения сохраняются в `historical_*`. Исключение для «наследованных» записей удалено: изменение такой строки через HTTP получает 403, а после миграции правка заголовка не возвращает статус «опубликовано». HTTP-запрос с `publishedAt` теперь тоже получает 403.
- **Проверка целостности сборки без запасного варианта.** Три маркера (`lib/flavor.baked.js`, `lib/flavor.lock.json` с SHA-256 и `studioFlavor` + `studioFlavorSha256` в `package.json`) должны присутствовать и совпадать, иначе код 78. Значения по умолчанию нет, `NODE_ENV` не влияет. `STUDIO_FLAVOR` учитывается только в исходниках (`scripts/` присутствует, не внутри `.app`, не Electron). Electron-оболочка дополнительно сверяет распакованные маркеры с замком `desktop/flavor.lock.json` внутри `app.asar`, который защищён ASAR integrity.
- **Модуль публикации (`meta.js`) не входит в TEST-сборку.** Сам модуль отказывается загружаться, если сборка не prod. Prod-сборка без `meta.js` не запускается (код 78).
- Тесты: `test:publish-guard` расширен (Keychain, миграция v1, прямые записи в БД, подделка маркеров собранного бандла). Отчёт: `docs/SECURITY_RECHECK_v1.2.3-test.md`.

**Исправления рисков**
- Восстановление БД теперь в два шага: `POST /api/restore/prepare` возвращает одноразовый токен (5 мин), затем `POST /api/restore {token, confirm:"ЗАМЕНИТЬ"}`. Перед заменой сервер автоматически делает копию SQLite (`VACUUM INTO`, `.sha256`). Старый одношаговый вызов отклоняется.
- SSRF при проверке интеграций (`lib/egress.js`): для каждой интеграции свой белый список хостов и портов. Локальные службы доступны только по loopback и на известном порту, внешние — только хосты из списка и только по https:443. Сервер разрешает DNS и проверяет каждый адрес. Блокируются частные сети, CGNAT, link-local, метаданные облака (169.254.169.254, fd00:ec2::254, 100.100.100.200), ULA, multicast и IPv4-mapped. Соединение идёт на проверенный адрес (нет окна для DNS-rebinding), редиректы не выполняются.
- `lib/keystore.js`: мастер-ключ больше не передаётся в argv. Он уходит hex-строкой (`-X`) через stdin `security -i`. Тест проверяет журнал argv.
**Контроль нагрузки**
- Чат Director (Ollama `/api/chat`) идёт через общую блокировку тяжёлых операций (`tryHeavy`), как Blender и video_render. Ollama никогда не работает одновременно с ними. Блокировку ждём `STUDIO_CHAT_WAIT_MS` (15 с). Если не дождались, ответ `202 {status:"busy_queued"}`, а запрос завершается в фоне (не дольше 10 мин). Если в очереди больше `STUDIO_CHAT_MAX_QUEUED` (3) запросов, ответ `429 queue_full`. Статический тест проверяет, что все вызовы `/api/chat` и `/api/generate` идут под блокировкой.

## 1.2.1-mac-preview — 3D Studio, этап C: ревью, версии, перерендер, экспорт (2026-10-21)
- **Референсы**: загрузка PNG/JPEG/WEBP в проект 3D Studio. Тип проверяется по сигнатуре файла, а не по расширению (SVG/HTML отклоняются). Лимиты: до 15 МБ на файл и до 20 файлов на проект. Файл хранится как `references/<sha256>.<ext>`, исходное имя очищается, повторная загрузка того же файла распознаётся. Файлы отдаются с `nosniff` и `CSP: sandbox`. **Ограничение:** референсы пока только хранятся и показываются; модель их не использует (это этап D).
- **Ревью**: кнопки «Утвердить», «Доработать» и «Отклонить» работают через `POST /api/jobs/:id/review` и только из статуса «Ждёт утверждения».
  - «Доработать» требует комментарий и создаёт новую версию на основе предыдущей. Параметры меняет ИИ, а без Ollama их меняют правила по комментарию (цвет, свет, ближе/дальше, кадры и т.д.). Предыдущий `.blend` сохраняется как резервная копия в `backup/`.

- **Перерендер**: свет, камера (расстояние, высота, фокус), turntable-кадры, движок, сэмплы, разрешение и FBX. Шаблон перезапускается в новую версию без агента OpenCode. Сервер принимает только эти поля и проверяет значения.

- **Просмотр GLB**: свой WebGL-просмотрщик `public/glb-viewer.js` (≈60 строк, без three.js и CDN, без `eval`). Строгий CSP `script-src 'self'` не изменён.

- Тесты: новый `npm run test:3c` (61 проверка). Он проверяет загрузки (подмену типа, SVG, превышение размера, пустой файл, traversal в имени и в id проекта), отсутствие CSRF-заголовка (403) и авторизации (401), подделку утверждения через общий API, повторное ревью, перерендер с неверными полями, белый список и traversal при скачивании, удаление с резервной копией, CSP и разбор реального GLB.

## 1.2.0-mac-preview — «Autonomous 3D Production», этапы A и B (2026-10-21)
**Этап A: исполнитель-агент через OpenCode server API**
- Director назначает 3D-задачи агенту **3D DESIGN** (агент включён, больше не «в разработке»). Задачу можно создать из чата Director или кнопкой «Создать 3D-модель» в 3D Studio.
- Новый клиент OpenCode server (`lib/opencode-client.js`) работает через `/global/health`, `/config`, `/session`, `/session/:id/prompt_async`, `/permission` + `/permission/:id/reply`, `/session/status`, `/session/:id/message`, `/session/:id/abort` и SSE `/event`. Basic Auth использует пароль из Keychain; версия OpenCode должна быть ≥ 1.1 (проверено с 1.19.3).
- Политика разрешений `lib/policy.js`:
  - shell запрещён;
  - доступ только к папке проекта;
  - защищённые файлы Blender агент не трогает;
  - удаление и публикация требуют подтверждения;
  - перед запуском проверяется конфиг сервера.
- Новый движок заданий `lib/jobs.js` хранит задания в отдельных таблицах SQLite `jobs`/`job_events`: статус, этап, попытки, лимиты повторов, checkpoint, артефакты, ошибка, heartbeat, журнал действий с id правил. Есть таймауты, отмена, повтор (автоматически 1 раз для временных ошибок, вручную до 3) и **продолжение после перезапуска с текущего этапа**; сиротские процессы Blender убиваются.
- Общий API: `POST/GET /api/jobs`, `/api/jobs/:id/{cancel,retry,confirm}`; внутренние модули `lib/services.js` (`jobsApi`, `blenderService`, `host3d`).
- Тяжёлые операции (Blender, Ollama) сериализованы (`lib/heavy-lock.js`).

**Этап B: Blender Automation Service**
- `lib/blender.js`: поиск Blender (macOS `/Applications`, PATH, путь из настроек), проверка версии ≥ 4.2 и Python API (движки, экспорт GLB/FBX) в фоновом режиме, запуск `-b --factory-startup --python-exit-code 3`, таймаут/отмена, разбор ошибок Python.
- Проверенный шаблон `blender/templates/scene_basic.py`:
  - сцена (стилизованный кот MOONKATTY или примитив), материалы, свет (three_point/sun/studio), камера, фон, анимация turntable (до 48 кадров);
  - сохранение `.blend`, **повторное открытие в новом процессе**, рендер PNG (Cycles CPU / EEVEE / Workbench), экспорт GLB/FBX.
- Версии проекта `projects3d/<id>/vNNN` с резервной копией предыдущего `.blend`; `project.json`; артефакты с sha256.

**3D Studio UI (минимум, RU/EN/UK):** поле задачи, «Создать 3D-модель», этапы и статус, журнал, PNG-превью, отмена, повтор, подтверждение, состояние Blender/OpenCode, настройки пути и модели. Референсы, утверждение/доработка/отклонение и экспорт из UI помечены «В разработке».

**Тесты:** `test:3d` с реальным opencode serve 1.19.3 + Basic Auth (мок-LLM вместо Ollama) и реальным Blender 5.2.2 headless; `test:policy`. Существующие тесты security, opencode, runner и smoke проходят.
