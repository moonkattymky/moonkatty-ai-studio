## 4. Модули

### Новости → видео

IMPLEMENTED и INTEGRATED в сервер TEST (`lib/news-video.js` + `services.videoRender`).
Публикации нет. Утверждение выпуска привязано к хешу текста и к галке «факты проверены» (QA-NV-002). Правка сбрасывает утверждение.
Длинные слова/URL/хэштеги режутся (`hardSplit`, S5-NV-01, `6a74a18`). Короткие куски после разреза дотягиваются до минимальной длительности (F-1, `9efce6e`).
Зависимости ffmpeg/ffprobe/rsvg проверяются до постановки задания (424 `video_deps_missing`, `d11c16c`).

Не закрыто, это и есть падение на Mac mini:

- Финальный прожиг в `media-automation/src/video/factory2.js` вызывает фильтр `ass='subs.ass'`. На ffmpeg, где у фильтра `ass` нет короткой формы `filename`, это даёт ровно `No option name near 'subs.ass'`, затем `Error parsing filter description` и `Invalid argument`. На ffmpeg 6.1.1 Ubuntu короткая форма ещё работает — поэтому Linux-прогон мог быть зелёным, а сборка Homebrew на Mac нет.
- Если libass не собран, фильтра `ass` нет вообще. Запасного наложения через SVG/`rsvg-convert` нет: rsvg используется для плашек, не для субтитров.
- Путь в filtergraph не экранируется (`:`, кавычки, пробелы, запятые).
- Автовыбора способа прожига нет.

Озвучка: `detectTTS` выбирает kokoro (если задана модель) → `say` на macOS → piper → espeak-ng. Тихого тона вместо речи нет. Отдельного повтора, если голос `Samantha` отсутствует, нет. На этой VM нет ни `say`, ни `espeak-ng`.

### Ссылки NASA и ESA

В коде студии: NASA `https://www.nasa.gov/news-release/feed/`, ESA `https://www.esa.int/rssfeed/Our_Activities/Space_News`.
Проверка HTTP с этой VM 2026-10-23: обе ленты **200**, `application/rss+xml`. Несколько материалов NASA и ESA тоже **200** (в том числе статьи на `science.nasa.gov`).
Парсер RSS раскодирует `&#038;`. Сами URL лент сейчас не 404.

Почему владелец видит «битую» ссылку из собранного приложения: `desktop/main.js` открывает внешний https только для короткого списка (Facebook, Instagram, GitHub, t.me, …). `nasa.gov`, `science.nasa.gov`, `esa.int` и остальные источники новостей в список не входят. Клик по `<a target="_blank">` глушится, окно не открывается. Это не обход allowlist: список надо расширить только официальными хостами источников, не всеми https.

### Approval Center

Цепочка подтверждения владельца на месте (хеш параметров, одноразовость, 409 consumed, самоподтверждение по правилам владельца). 3D и `opencode_task` на POST `/api/jobs` отвечают 403 `feature_disabled`. Ослаблять нельзя. Демо-режима видео с явно тестовыми данными нет: любой рендер идёт только после утверждения, и отдельной кнопки «это тест, факты не проверены» тоже нет.

### Запуск сервера и выбор версии (этап C)

В `5013621` уже есть: `/api/health` отдаёт `version` и `commit`; оболочка считает сервер чужим, если другое приложение/flavor, и устаревшим, если другая version или (когда оба знают commit) другой commit; на macOS `launchctl kickstart -k`, вне macOS SIGTERM по pid из health; при `EADDRINUSE` тот же version выходит с кодом 0, иначе 3.
Дыра: сервер при занятом порте сравнивает flavor и version, но **не commit**. Оболочка при разных commit считает сервер устаревшим, а процесс сдаётся с кодом 0 («уже запущен») и оставляет старый код. Отдельного теста на это нет. На Mac mini не проверялось.

### Telegram и YouTube

Библиотеки есть (`media-automation/src/auth/telegram-setup.js`, `youtube-oauth.js`): getMe, PKCE, loopback, секреты через переданный secret store. В сервер панели и в Keychain-счета студии **не подключены**. Кнопка в UI не равна подключению. Пароли соцсетей не запрашиваются и запрашиваться не должны.
Keychain для мастер-ключа и отдельных секретов уже есть (`lib/keystore.js`, `security -i`, секрет не в argv). На Linux Keychain нет — это BLOCKED для реальной авторизации, не повод писать токен в репозиторий или в открытую базу.
Без токена бота и OAuth-клиента YouTube объявлять «подключено» нельзя.
